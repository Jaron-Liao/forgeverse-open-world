## 0. 项目实读结论（先看清现实，再谈重构）

### 0.1 它现在是什么
ForgeVerse 是一个**单页 3D 造物工作台**（Three.js r160，26 个 ES 模块，纯静态 + 腾讯云 wb_saves）。不是多页游戏网站，也不是关卡制游戏。已有：几何体/布尔/细分/阵列建模、顶点与纹理绘画、PBR 材质与程序化贴图、种子地形与雕刻、9 种天气、四生态（草原/雪原/沙漠/赛博）、第一/三人称漫游、全屏世界管理页 + 多世界独立存档、自动保存、PWA。

### 0.2 它现在不是什么（关键缺口，全库关键词扫描证实）
| 你要的能力 | 现状 | 关键词命中 |
|---|---|---|
| 首页/游戏主页/沙盒/关卡/排行/帮助/关于 多页面 | 只有 1 个 HTML + 7 侧栏 tab + 3 全屏层 | 页面跳转体系不存在 |
| 方块/元素网格搭建 + 破坏 | 几何体拼装，无体素网格 | 方块/元素规则 0 |
| 物理（重力/碰撞/液体） | 无物理引擎 | physics/gravity/collision/液体 全 0 |
| 关卡 / 挑战 / 计分 / 星级 | 无 | challenge/score/关卡 近乎 0 |
| 排行榜 | 无 | leaderboard/排行榜 0 |
| 胜利/失败逻辑、难度曲线 | 无失败态（概念文档明确"不设失败状态"） | 胜利 0 |
| 音效反馈 | 无 | audio/sound/音效 全 0 |
| 成就系统 | 仅"完成任务数"计数（4 级） | 极简 |
| 分享码 / 社区展示区 | 仅 GLTF/JSON 导出 | share 1 文件 |

### 0.3 方向性冲突（已由用户拍板）
旧概念文档立场是"工具优先、不设关卡/失败、不做任务玩法重做"。用户本次明确转向：
- **产品定位：双模式并存** —— 自由创作模式（无胜负，保留现有）+ 挑战关卡模式（计分/星级/胜负/难度曲线，新建）。
- **物理：完整物理沙盒** —— 引入轻量物理引擎，支持重力/碰撞/液体。
- **站点结构：多页外壳 + 单页游戏** —— 新建独立静态页（首页/游戏主页/关卡选择/排行榜/帮助/关于），游戏本体仍是单页应用（SPA），通过路由切换视图。
- **GitHub：重新授权后由 Agent 全权建分支/PR/推送**（用户选择重新授权）。

## 1. 完善后的需求提示词（可执行版）

> 以下每条 = [需求] + [技术实现路径] + [验收标准]，可直接派工。

### 1.1 第一阶段 · 项目梳理与需求完善
- **完成标志**：本目录 `docs/REQUIREMENTS_V9.md`（本文）+ 页面/内容/机制/问题四张清单。已交付。
- **验收**：每条需求都能对应到后续 Story 编号，无悬空描述。

### 1.2 第二阶段 · GitHub 版本管理
- **需求**：初始化/接入 Git；分支策略 main/dev/feature/*；每个重大改动独立 feature 分支；规范 commit message；CHANGELOG.md；PR 合并；可回滚。
- **技术路径**：等待用户重新授权 GitHub（MCP 写 403 已验证）→ 用 `create_branch` + `push_files` + `create_pull_request`（或本地 git + 用户 push）。约定 commit 格式 `type(scope): subject`（feat/fix/docs/perf/chore）。
- **验收**：main/dev 两长期分支存在；至少 1 个 feature 分支 + 1 次 PR；CHANGELOG.md 记录全部变更；`git log` 可追溯每个板块。

### 1.3 第三阶段 · 全站重设计
- **需求**：统一视觉系统；清晰导航（顶部栏 + 移动端汉堡 + 面包屑 + 页脚）；三端响应式（移动优先）；合理动效。
- **技术路径**：产出 `docs/DESIGN_SYSTEM_V9.md`（配色/字体/间距/圆角阴影/图标/按钮卡片规范）；沿用并扩展现有暗金玄墨体系（ART_BIBLE 已定 hex，避免推倒重来）；CSS 变量集中；`@container`/`clamp()`/`prefers-reduced-motion`；触控目标 ≥44px。
- **验收**：风格指南文档存在；7 个页面视觉一致；任意核心页 3 次点击内可达；桌面/平板/手机三视口无溢出。

### 1.4 第四阶段 · 沙盒核心玩法
- **需求**：探索—收集/解锁—建造破坏—保存分享循环；方块/多材质；物理；新手教程；成就；挑战关卡；即时反馈；Undo/Redo；难度与胜负；自由模式；作品保存/加载/截图/分享码/社区展示。
- **技术路径**：
  - 方块系统：新增体素网格模块（分块 chunk + 稀疏存储），与现有几何体系统并存（双模式）。
  - 物理：引入轻量开源物理（如 cannon-es / rapier 的兼容版本，需验证可离线化）或自研 AABB 重力碰撞 + 简化液体元胞自动机；以不破坏 60fps 为上限。
  - 关卡：JSON 关卡定义（限定元素/时间/目标结构），关卡引擎校验完成度并计分（星级 1–3）。
  - 反馈：放置/删除动画 + Web Audio API 合成音效（零资源）+ 光标/气泡 + 复用现有 undo/redo 栈。
  - 分享：作品序列化为短码（Base64+压缩）或云端 share 表；社区展示页读取。
- **验收**：能放/删方块且重力碰撞生效；至少 3 个挑战关卡可通关并给星；自由模式无胜负；每个操作有视听反馈；分享码可导入还原。

### 1.5 第五阶段 · 质量与性能
- **需求**：模块化注释；60fps；首屏优化；图片压缩；跨浏览器。
- **技术路径**：渲染已用 scissor 多视窗 + 4 档画质；补性能预算脚本、懒加载、WebP 缩略图、浏览器兼容降级。
- **验收**：主循环 ≥55fps（中档机）；首屏 <3s；Chrome/Edge/Safari/Firefox 均可打开核心流程。

## 5. 建议实施顺序与里程碑

1. **M1（P0 前半）**：授权 GitHub → 建仓/分支/CHANGELOG → 设计系统 v9 → 游戏主页 SPA 容器。里程碑：版本可追溯 + 新主页可跑。
2. **M2（P0 后半）**：体素方块 → 重力碰撞 → 视听反馈/Undo → 存档补强。里程碑：**可玩的方块沙盒**（双模式中的自由模式成型）。
3. **M3（P1）**：静态页 + 导航 + 响应式 → 关卡页 + 计分星级胜负 → 成就教程 → 液体。里程碑：**双模式完整**（自由 + 挑战）。
4. **M4（P2）**：分享码 → 社区墙 → 排行榜 → 云数据。里程碑：作品可分享、可展示、云端并发。
5. **M5（P3）**：IndexedDB → 性能 → 跨浏览器 → 回滚。里程碑：生产级质量。

**关键路径**：P0-1（授权）→ P0-4（方块）→ P0-5（物理）→ P1-4/5（关卡胜负）→ P2-4（云）。
**最大风险**：完整物理沙盒在浏览器保持 60fps（需在 M2 早期做技术验证，失败则降级为轻量物理并回调用户）。
